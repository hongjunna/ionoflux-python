# IonoFlux API 이용약관 개정 제안

**검토 초안 / 미시행 / 2026-10-20.** 운영 주체·시행일·준거법·적용 버전은 미확정이며 현재 약관/서비스를 바꾸지 않는다. 아래는 사용자가 제시한 정책을 서비스 이용계약으로 구체화하는 안이다. 기존 약관·개별 계약·공급자 권리와의 충돌 및 동의 방식은 최종 시행 전 별도로 검토한다.

## 1. 적용 범위 제안

이 약관안은 IonoFlux API에 접속해 조회·활용하는 서비스 이용에 관한 것이다. 호출 도구가 공식 SDK, curl, 직접 작성한 HTTP 클라이언트 중 무엇인지와 관계없이 API 이용 범위를 대상으로 한다. SDK 코드의 복제·수정·재배포 이용권은 별도 SDK 라이선스가 정한다. 데이터 공급자의 권리와 원 라이선스는 별개이며 본 약관이 대체하거나 축소하지 않는다.

## 2. 허용 범위 제안

확정된 API 이용 한도와 원 공급자 조건 안에서 비상업적인 개인 학습·취미·교육·공익 연구를 허용하는 안이다. “무료 제공”만으로 비상업적이라고 보지 않는다. 제품 개발·기업 사업 의사결정·고객 납품, 유료 제공·구독·광고·제휴/판매 유도 등에 API 결과를 쓰는 목적은 사전 서면 허가 심사 대상으로 제안한다.

다음은 최종 정책 결정이 필요하다: 대학/공공연구기관의 기업 지원 과제, 연구 결과의 기술이전·유료 보고서, 비영리 기관의 유료 활동, 자발적 기부와 광고성 후원의 구분. 표준 SDK 코드가 허용하는 기관 이용과 API 접속에 제안하는 심사는 다른 층이다. 이미 승인된 코드 이용권이 API 약관안 때문에 취소된다고 쓰지 않는다.

## 3. 사전 서면 허가 제안

이용 목적·주체·서비스/배포 범위·사용 데이터/공급자·재배포·기간·한도를 명시해 권한 있는 운영자에게 요청한다. 허가는 SDK 코드와 API 접속 중 무엇을 포함하는지 각각 특정한다. 협의 또는 요금 지불만으로 자동 허가되었다고 보지 않는다. 실제 상업 계약 템플릿·승인 담당·문의 주소는 운영자가 확정한다. 본 초안은 허가를 발급하지 않는다.

원 제공자에게 별도 승인이 필요한 데이터는 IonoFlux 허가만으로 사용할 수 없다. 예를 들어 상업 이용이 가능한 데이터와 NC 데이터가 섞인 결과는 공급자별로 조건을 확인한다. 권리를 확보하지 않은 데이터에 상업적 재허가를 약속하지 않는다.

## 4. IonoFlux 출처 표시 의무 제안

API 결과를 서비스·문서·연구·프로젝트에 활용할 때 서비스명 **IonoFlux**와 공식 URL **https://ionoflux.runvia.app** 을 확인하기 쉬운 위치에 표시한다. 권고 위치: 차트/데이터 화면의 credit 또는 접근 가능한 출처 페이지, 앱의 데이터 출처/정보 화면, 논문 데이터·방법/참고문헌, Python 프로젝트 README·보고서·데이터셋 메타데이터. 비공개 연구/사내 프로젝트는 내부 문서에 표시하고 공개 게시를 강요하지 않는 안이다.

개별 숫자마다 반복하거나 모든 화면에 로고를 상시 표시하도록 요구하는 안은 아니다. 결과를 캡처·별도 데이터 파일로 배포할 때도 적절한 캡션/sidecar 메타데이터를 함께 제공한다. 이는 SDK 사본의 Required Notice 전달 의무와 구분한다. 구체적인 화면 위치·링크 방식·오프라인 URL 표기 기준은 별도 승인한다.

## 5. 원 공급자 표시·품질 메타데이터 제안

응답의 source·attribution·unit·time·last_updated와 적용 라이선스를 보존한다. 공급자가 요구하는 명칭·URL·라이선스 링크·DOI·변경 표시 등을 별도로 충족한다. IonoFlux만 적고 NOAA/GFZ/SILSO 등 실제 사용 공급자의 표시를 생략하지 않는다. 사용하지 않은 공급자 이름을 일괄 붙이지 않는다. source 식별자가 별칭인 경우 API 출처 목록으로 대응시킨다.

빈 배열·null·수집 지연은0이나 정상으로 바꾸어 설명하지 않고 관측·예측·모델 값을 구분한다. 파생 집계·보간·변환은 방법과 적용한 변경을 알린다. 라이선스 표시 자체에 데이터 사용 허가 여부가 불명확하면 원 권리자 조건을 먼저 확인한다.

## 6. 키·요청 예산·기술 운영 제안

Server 키를 브라우저·공개 코드·로그·URL에 노출하지 않는다. 허가받은 플랫폼·도메인·서비스 범위를 준수한다. 서비스가 제공하는 한도·Retry-After를 따르고429를 우회하려고 계정·키를 바꾸지 않는다. 대량 수집·미러링·원본 재판매·캐시 재배포·API 대행 제공은 별도 범위 협의 대상으로 두되 원 데이터의 독립 이용권을 제한하는 재라이선스로 표현하지 않는다.

## 7. 서비스 한계·정지·변경 절차 제안

관측 누락·공급자 지연·모델 불확실성·서비스 중단 가능성을 설명하고 안전 필수 의사결정의 적합성을 자동 보증하지 않는다. 법정 책임·소비자 권리를 임의 면제하는 문구는 쓰지 않는다. 중대한 보안·남용 상황의 일시 제한과 통지/이의 절차, 일반 위반 시 통지·시정 기회는 운영 절차와 함께 정한다. 법률 근거 없이 즉시 영구 정지·데이터 권리 소급 취소를 포괄 선언하지 않는다.

변경 이력·시행일·동의 화면·기존 이용자 유예/통지·개별 계약 우선순위·준거법/분쟁 절차는 최종 검토 항목이다. 현재 개발자 페이지에는 원 공급자 credit 안내가 있지만 이를 본 약관안의 시행 증거로 간주하지 않는다. API 키 정책·플랫폼 인증·한도는 이번 작업에서 변경하지 않는다.
