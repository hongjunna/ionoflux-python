## Fixed budget and checks

The script uses the current SDK with timeout10s per HTTP operation and max_retries0, plus an HTTPTransport(retries=0) wrapped by a transport enforcing GET, official origin, allowlisted routes and a global maximum9 requests. There is no pagination, parallelism, redirect following, backoff or reauthentication. Every failure stops immediately, including401/403/429. The context manager closes the client/transport on success or failure. The workflow deadline bounds unusually slow responses; timeout is not a promise of a ten-second total job.

Sequential checks: current, SFI, observed Kp (forecast disabled), SFI statistics, alerts, NOAA scales, sources, summary data-status and newest SFI status detail. Series limits are3; series/statistics use an explicit last7days UTC window, alerts last1day/limit3. Six authenticated GETs plus three public GETs are the complete nine-call budget; public metadata requests omit the key. A server error does not trigger retries or a follow-up request.

The captured OpenAPI schema validates typed responses with a UTC date-time format checker. Known timestamp fields in generic metadata are checked recursively. Series units (SFI=sfu/Kp=index), explicit swpc source, attribution and metadata containers are checked. Parsed raw JSON must equal SDK data; no normalization/filling removes nulls, empty arrays, unknown fields, units or attribution. Nullable/empty cases are accepted and independently tested offline; a live pass does not claim that a null branch or every data provider was observed. Generic server dictionaries cannot establish every nested field contract; statistics has no attribution field, and source terms come from sources(). Snapshot drift fails validation and requires source/OpenAPI review before changing expectations; do not relax checks to conceal incompatibility.

Logs and the job summary contain only fixed check names, integer/null HTTP status, PASS/FAIL, bounded request count and resource-close status. Response bodies, exception details/tracebacks, timestamps/measurement values, headers, key, environment values and arbitrary server strings are never serialized. HTTP logging is disabled. There are no response artifacts. A failed result exits1; setup/configuration failures make zero requests where possible. This is live compatibility acceptance, distinct from Mock CI and not a data-quality/service-availability guarantee.
