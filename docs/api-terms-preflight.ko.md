# API 약관 최종 승인·시행 전 법률 및 공급자 권리 체크리스트

2026-10-20. **API 약관은 초안 상태이며 미시행이다.** SDK의 PolyForm Noncommercial 1.0.0 채택·Required Notice 발급은 승인됐지만 API 약관 시행이나 운영 사이트 변경 승인은 아니다. 본 체크리스트는 검토할 항목이지 실사 완료 선언이 아니다. 기존 api-terms-proposal.ko.md 초안은 변경하지 않았다.

## 1. 운영 주체·권한·SDK 코드 권리

- 법적 운영 주체의 실명/법인명·주소·계약 담당·통지 및 상업 허가 창구를 확인한다. GitHub 계정이나 서비스명을 법인 등록명으로 간주하지 않는다.
- SDK 코드의 기여자·고용/양도 관계·외부 코드·의존성 라이선스와 상업 계약의 권리/대리권을 확인한다. 표준이 이미 허용하는 기관 이용에 중복 상업 허가를 요구하지 않는다.
- 개인/기업 기초 연구·산학 과제·기관의 유료 활동·기부/후원의 구분을 API 서비스 층에서 승인하고, 코드 라이선스를 소급 축소하는 표현을 제거한다.

## 2. 제3자 데이터별 권리표

공급자·데이터셋·버전·획득 경로·현재 약관/라이선스 URL·검토일·권리자·인용/DOI·가공/재배포·상업 허가 가능 여부·증빙·재검토 조건을 표로 유지한다. `sources.py`의 요약 문자열이나 API의 attribution만으로 법률 실사를 완료했다고 보지 않는다.

- [NOAA](https://www.swpc.noaa.gov/) 자료는 실제 제품별 출처·제3자 포함 자료·공식 기관명/로고 사용·보증 오인 금지와 적용 정책을 확인한다. 미국 정부 자료라는 이유로 모든 포함 자료를 무조건 동일 취급하지 않는다.
- [GFZ](https://kp.gfz.de/en/about-kp)의 CC BY4.0 표기·기관명·권장 DOI/인용·변경 표시·그림 및 데이터 범위를 확인한다. 원 라이선스의 이용권에 새 NC 제한을 재라이선스하지 않는다.
- [SILSO](https://sidc.be/SILSO/citations)의 NC·인용/DOI 및 대상 시리즈 조건을 확인한다. API 상업 계약으로 원 공급자 NC가 해제된다고 약속하지 않는다.
- GIRO/KC2G는 개별 관측소·집계 feed·모델/관측 자료의 권리 및 원 출처/인용·상업 사용 범위를 공식 정책·제공자에게 확인한다. 사이트 소스 코드 라이선스를 데이터 라이선스로 대체하지 않는다.
- PSK Reporter·WSPRnet/WSPR.live는 원 수신 보고의 보관·재배포·상업 사용·공개 결과 조건·집계 결과와 원본의 차이·운영자 허가 범위를 확인한다. 호출부호·위치 등 데이터의 개인정보성도 별도로 검토한다.
- GeoNames·OpenStreetMap/Nominatim은 CC BY/ODbL 및 제품별 attribution·파생 DB·재배포 조건, 지오코딩 서비스 이용 정책을 별도 확인한다. SDK 코드의 조건을 지도/지리 데이터에 자동 적용하지 않는다.
- 여러 공급자를 혼합한 요약·통계·MUF/전파 모델의 경우 산출물의 의존 자료·재허가 범위·상업 허가 미확보 자료의 분리 가능성을 검토한다. 원 제공자 권리를 확보하기 전 일괄 상업 허가를 판매하지 않는다.

위 항목 중 GFZ/SILSO·CC 원문 확인 외 모든 제품/공급자별 권리 실사가 완료됐다고 주장하지 않는다. [CC BY](https://creativecommons.org/licenses/by/4.0/deed.en)와 [CC BY-NC](https://creativecommons.org/licenses/by-nc/4.0/deed.en)의 차이를 공급자별로 적용하고 기관의 코드 사용 허용을 데이터의 NC 면제로 확대하지 않는다.

## 3. API 계약과 출처 표시의 범위

- 약관 적용 대상이 API 접속·서비스인지, 원 데이터 자체의 권리를 재정의하는지 구분한다. 표준/공급자가 이미 허용한 이용권에 부당한 추가 제한을 얹지 않는지 검토한다.
- IonoFlux 서비스명·URL 표시의 대상(웹/앱/논문/사내 연구/파일), 위치·링크·오프라인 대안·캡처/파생물 처리를 구체화한다. Required Notice 전달을 모든 화면 표시로 오인시키지 않는다.
- 실제 source별 원 제공자 표시·라이선스 링크·DOI·변경 및 결측/관측·예측 구분과의 병행을 확인한다. 승인 없는 공식 후원/보증·로고 사용을 요구하거나 허용하지 않는다.
- 캐시·대량 호출·미러링·재판매·파생 집계·재배포의 허용 범위와 요청 예산을 정한다. 키 유형·권한·요금·서비스 한도 변경은 별도 구현·승인 사항으로 둔다.

## 4. 동의·시행·변경·구제 절차

- 기존 약관·개별 계약·외부 문서의 실제 존재와 적용 범위를 확인한 뒤 개정 비교표·버전·시행일을 정한다. 개발자 페이지의 권고성 출처 안내를 이미 동의받은 강제 계약으로 간주하지 않는다.
- 계정/키 발급의 동의 UI·동의한 버전과 시각의 증거·개인정보 최소 보관·기존 이용자 통지/유예·거부 시 처리·접근 가능한 언어를 검토한다. 소급 적용을 임의 선언하지 않는다.
- 준거법·관할·소비자/공공기관 특칙·수출/제재 등 적용 법률, 보증/책임 제한의 유효성, 중단·위반 통지·시정/이의 절차·서비스 종료 시 처리 방안을 검토한다. 모든 책임·법정 권리를 포괄 면제하지 않는다.
- 개인정보 처리방침과 계정/API 로그·호출부호/위치·IP 보관·목적/국외 처리·삭제 절차가 충돌하지 않는지 검토한다.
- 권한 있는 담당의 최종 법률·공급자 실사 승인과 별도 운영 반영 승인을 받은 후에만 현행 사이트를 바꾼다. 승인 후에도 시행일·원문·변경 이력을 보존한다.
