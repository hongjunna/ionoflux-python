# SDK 라이선스 검토 — PolyForm Noncommercial 1.0.0 우선 후보

**검토 초안 / 미채택 / 2026-10-20.** 법적 권한을 부여하는 문서가 아니다. LICENSE는 미정 안내 그대로이며 pyproject에 라이선스를 지정하지 않았다. 현재 운영 약관도 수정하지 않았다. 최종 채택 전 권리자·운영 주체와 법률 검토가 필요하다. 기준은 사용자가 제시한 정책이며 아래 해석과 제안은 확정 약관이 아니다.

## 판단 요약

원문의 [Notices](https://polyformproject.org/licenses/noncommercial/1.0.0#notices)는 소프트웨어 사본 전달에 따른 고지 보존 의무다. 재배포 시 서비스명·URL 고지를 유지시키는 용도로 적합하지만, 서버에서 SDK만 실행하고 데이터·그림만 공개하는 경우까지 화면 표시를 강제하는 근거로 삼기에는 부족하다. 고지의 문장에 UI 의무를 써 넣는 것만으로 별도의 행위 의무가 확실히 생긴다고 해석하지 않는다.

[공식 원문](https://polyformproject.org/licenses/noncommercial/1.0.0)의 기관 허용 조항은 교육·자선·공공연구 등 열거된 기관의 이용을 재원·관련 의무와 관계없이 허용한다. 따라서 산학 연구·기관 수익 활동을 SDK에서도 모두 사전 허가 대상으로 만들려는 정책과는 차이가 있다. 기업 내부 연구도 명칭만으로 비상업적이라고 확정하지 않는다. 광고·유료화·영리 목적, 이용 주체, 기관 예외를 함께 판단해야 한다.

## 세 가지 권리 층의 분리 제안

| 층 | 담당 문서 | 검토 방향 |
|---|---|---|
| IonoFlux가 권리를 가진 SDK 코드 | 향후 승인된 LICENSE + 고지 | 표준 PolyForm NC를 그대로 쓸지 먼저 결정. 상업적 코드 사용은 별도 서면 계약 가능 여부를 권리자 확인 |
| IonoFlux API에 대한 접속·서비스 이용 | 향후 API 이용약관 | 무료 비상업 이용 범위, 상업 이용 심사, IonoFlux 서비스명/URL의 화면·산출물 표시, 키/한도·캐시·정지 절차를 독립 정의 |
| 응답의 원 제공자 데이터 | 공급자별 원 라이선스·정책 | API 경유 여부와 별개로 원 조건 유지. SDK/API 허가가 제3자의 NC·표시·기타 제한을 면제하지 않음 |

SDK 라이선스를 피하려고 다른 HTTP 클라이언트를 사용해도 API 접속 조건은 별개다. 반대로 API 약관으로 SDK를 API 없이 쓰는 행위까지 새로 제한하거나 기존 코드 이용권을 소급 취소한다고 쓰지 않는다. IonoFlux는 권리를 보유하지 않은 데이터의 상업 이용을 허가할 수 없다. 예를 들어 GFZ CC BY 조건이나 SILSO NC 조건은 각각 독립적으로 검토한다.

## Required Notice 운영안 — 후보일 뿐 현재 발급 아님

채택된다면 표준 본문을 수정하지 않고 별도 고지 파일/배포 메타데이터에 서비스 식별문을 두는 안이다. 아래는 설명용 예시이며 현재 효력이 있는 Required Notice가 아니다.

`초안 예시(미발급): Required Notice: IonoFlux — https://ionoflux.runvia.app`

상호/저작권자 명의는 아직 확인하지 않았으므로 법인명·연도·저작권 문구를 임의로 만들지 않는다. 승인 후 실제 고지는 wheel/sdist 및 SDK를 포함한 재배포물의 라이선스/고지 위치에서 함께 전달되도록 패키징 인수를 추가한다. 이 문서 자체를 NOTICE나 실제 LICENSE 대체물로 사용하지 않는다.

| 요구 | 표준 고지로 처리 | 별도 합의/문서 |
|---|---|---|
| SDK 사본과 함께 이름·URL·라이선스 고지 전달 | 적합 | 고지 문구/배포 위치 승인 필요 |
| 백엔드만 SDK를 쓰는 사이트의 데이터 화면 credit | 자동 보장되지 않음 | API 약관의 표시 의무 |
| 논문·차트·데이터셋에 IonoFlux 경유 사실 표시 | 자동 보장되지 않음 | API 약관·인용 가이드, 원 공급자 조건 |
| API 없는 SDK 사용에도 항상 광고성 화면 표시 강제 | 미충족 | 정말 필요한 요구인지 결정; 필요하면 별도 코드 이용계약/맞춤 라이선스 법률 검토 |
| 상업적 이용에 사전 서면 허가 | 목적·기관 예외 확인 필요 | SDK 상업 계약과 API 상업 계약의 권리 범위를 각각 명시 |

## 표준을 유지하는 안과 변경하는 안

우선 검토안은 **표준 SDK 코드 라이선스 + 별도 API 서비스 약관**이다. 기관 예외까지 포함한 표준 문구를 수용하면서, API에서는 별도 승인한 이용 범위·출처 표시를 합의한다. 서비스 이용계약의 동의·통지·적용 시점과 기존 사용자 처리 방안을 마련해야 한다. 기존 사용자의 코드 권리를 단순 README 수정으로 축소하지 않는다.

SDK에도 기관 예외를 없애거나 모든 실행에 화면 고지를 강제하려면 맞춤 라이선스/상업 계약을 별도로 검토해야 한다. 표준 이름을 그대로 붙이고 본문에 제한을 덧붙이는 방식은 피한다. 프로젝트의 [라이선스 원문 이용 지침](https://github.com/polyformproject/polyform-licenses/blob/1.0.0/README.md)은 수정본에서 PolyForm 명칭·도메인 언급 제거를 요구한다. 추가 이용 제한을 걸고도 표준 SPDX 식별자만으로 표시하지 않는다.

비상업 제한은 [OSI 정의의 사업 분야 제한 금지](https://opensource.org/osd)에 맞지 않으므로 채택 시에도 “OSI 오픈소스”라고 설명하지 않는다. 후보를 검토한다는 사실만으로 현재 저장소가 해당 라이선스나 일반 사용 허가를 얻은 것은 아니다.

## 공급자 조건을 약화시키지 않는 기준

[GFZ Kp 데이터 안내](https://kp.gfz.de/en/about-kp)는 CC BY4.0과 원 출처 표시를 안내한다. [SILSO 인용 정책](https://sidc.be/SILSO/citations)은 NC 조건과 별도 인용을 안내한다. [CC BY4.0](https://creativecommons.org/licenses/by/4.0/deed.en)의 원 이용권에 추가 제한을 얹어 제3자 데이터 전체를 IonoFlux 전용 NC 데이터로 재표시하지 않는다. 서비스 접속 계약과 원 데이터 자체의 권리 제한은 구분한다. [CC BY-NC4.0](https://creativecommons.org/licenses/by-nc/4.0/deed.en)은 PolyForm 코드와 별도 조건이므로 코드의 기관 예외를 데이터에 자동 확장하지 않는다.

현재 서비스 `backend/app/sources.py`와 개발자 페이지의 원 공급자 표시 안내는 확인했다. 저장소 내 독립 API 약관 페이지는 확인하지 못했으므로 외부 약관/기존 계약의 존재 여부는 운영자 확인 대상으로 남긴다. 기존의 권고성 안내를 이미 강제 약관으로 시행 중이라고 간주하지 않는다. 공급자 목록 전체에 대한 권리 실사 완료도 주장하지 않는다.

## 승인 전 남은 결정

표준 기관 예외 수용 여부, 화면/산출물 표시 의무의 적용 대상과 위치, 기업 연구/광고/후원/산학 과제의 기준, SDK·API 각각의 서면 허가 주체와 범위, 약관 동의/시행일/기존 사용자 처리, 공급자별 상업 재허가 가능성을 결정해야 한다. 이 검토는 개발·실 API 인수·CI를 중단하지 않으며 실제 라이선스 채택·약관 개정·외부 배포 승인과 분리한다.
